# ASAS Engineering Master Skill

Use this skill for any material ASAS engineering task. It is a workflow skill, not a replacement for AGENTS.md or canonical contracts.

## Authority

1. Founder/product decisions within founder authority.
2. Verified runtime/database reality for existing brownfield facts.
3. Approved canonical architecture, ADRs, contracts and registers.
4. Authorized task packet.
5. Implementation.
6. Historical/source-package material only as research evidence.

The supplied v1.6.1 source package is for lead-architect research/provenance. Never promote it directly into implementation.

## Execution loop

```text
IDENTIFY → LOAD → INSPECT → RESEARCH → RECONCILE → MODEL → CONTRACT → AUTHORIZE → IMPLEMENT → TEST → ADVERSARIAL REVIEW → VERIFY → EVIDENCE → CONVERGE
```

## Mandatory skills

- repository forensics and provenance;
- DDD and bounded-context modeling;
- aggregate/invariant design;
- command/query and state-machine contracts;
- event/outbox/idempotency design;
- tenancy/RBAC/RLS/security engineering;
- PostgreSQL/schema/migration/concurrency engineering;
- TypeScript/React/Next.js application architecture;
- API/integration/webhook design;
- design-system and Figma-to-code integration;
- accessibility/localization/RTL;
- browser/E2E/visual regression testing;
- CI/CD and architecture-as-code;
- observability/SLO/performance/recovery;
- threat modeling and AI safety;
- dependency/supply-chain hygiene;
- documentation/provenance/evidence management.

## Stop conditions

Stop and mark BLOCKED or FOUNDER-DECISION-REQUIRED for unresolved product scope, bounded-context ownership, financial semantics, legal interpretation, tenant authority, destructive production operations, security exceptions, irreversible external side effects or missing critical evidence.

## Change discipline

Prefer local-first work. Never use a remote production database as a design playground. Never fabricate commands, tests or evidence. Never close a gate because documentation exists.

## Required result

Every material change must leave a trace:

`Task → authority → decision → files → tests → verification → commit → gate/checkpoint`.
